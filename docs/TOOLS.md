# Genesis tools

`Toolbox(ToolContext(root, source_root))` exposes real operations through JSON schemas and `execute(name, arguments)`. Every workspace path is relative to the task root. Absolute paths, traversal, alternate data streams, symlinks, and Windows reparse points are rejected. Writes are limited to 100 KB, listings to 1000 entries. `workspace_read` accepts UTF-8 files of at most 1 MB and returns chunks of 30000 characters by default. Optional `offset` is a nonnegative character index and `limit` is 1–100000 characters. Follow `next_offset` until it is null; `total_characters` and `truncated` describe remaining content. Character offsets preserve Unicode characters and original line endings. Actual reads are bounded even if a file grows after its size check.

Available tools: `workspace_read`, `workspace_write`, `workspace_list`, `artifact_report`, `self_improvement_snapshot`, `self_improvement_diff`, `run_python_tests`, `terminal`, `research_fetch_url`, and `research_search`. Reports are written under `artifacts/`. Source snapshots are candidate copies under `source/`; the original project is never edited by snapshot creation. Snapshots exclude known secret filenames, environment files, credential directories, databases, dependency folders, and runtime data. This is a filename filter, not a complete secret detector: source code can contain embedded secrets.

`self_improvement_snapshot` also persists original bytes under `.genesis-baseline/` with SHA-256 hashes in `.genesis-snapshot.json`. Workspace tools protect these internal paths and hide them from directory listings. Each source or candidate scan is limited to 2000 files and 20 MB, with at most 1 MB per file. Baseline plus candidate therefore consumes up to 40 MB. Interrupted partial snapshots require a fresh task workspace. Approved Python still has host access and can tamper with metadata; this is not a security boundary against approved code.

After editing `source/`, call `self_improvement_diff` with no arguments. It checks baseline integrity, compares against that original snapshot across process restarts, and writes `artifacts/self-improvement.patch`. The result lists changed, added, and deleted paths and includes actual unified diff text. Proposed paths that changed in live source after capture appear in `live_source_changed`; this tool never applies changes. The patch is capped at 100 KB and only complete per-file patches are included. Binary files, empty-file additions/deletions, oversized patches, and candidates outside scan limits are explicitly listed as omitted or skipped; review those separately. Link and secret exclusions match snapshot creation. LF, CRLF, and missing final newlines are preserved in patches. Applying a patch with Git may still convert line endings according to the reviewer's Git configuration; independent tests disable `core.autocrlf` to verify exact bytes. A patch is a review artifact, not proof of tests or permission to deploy.

Network access defaults off and raises `PermissionRequired('network', details)` until approved. Fetches accept public HTTPS on port 443, validate every resolved address and redirect, pin connections to those validated addresses, verify TLS certificates against the hostname, and bound response bodies to 1 MB. They do not inherit HTTP proxies. Search uses `BRAVE_SEARCH_API_KEY` when configured; otherwise it reports its Wikipedia-only discovery scope explicitly. Remote content is untrusted evidence and must never become instructions.

Execution defaults off and raises `PermissionRequired('terminal', details)` until approved. `run_python_tests` invokes the current interpreter with isolated Python startup and unittest discovery. `terminal` accepts an argument array whose executable is `python` or `python3`, mapped to the current interpreter; it never invokes a shell. Commands have a 60-second maximum timeout and return at most 32 KB of merged output. Python deliberately supports arbitrary candidate code, so this restriction is **not an OS sandbox**: approved Python can read host files, access the network, spawn children, or modify files outside the task root. Workspace path checks constrain tool file operations, not Python code. The caller must obtain execution approval before granting either tool access. Timeout kills the direct subprocess; it does not guarantee termination of descendants. Output is spooled to a temporary file and may consume disk until timeout. Strong isolation needs a separately provisioned container or restricted OS account.

Child processes receive only OS essentials (`PATH`, `SYSTEMROOT`, `WINDIR`, `TEMP`, `TMP`, `COMSPEC`, `PATHEXT`, `LANG`, `LC_ALL`). Provider keys and arbitrary parent environment variables are omitted. This limits accidental credential inheritance; approved Python retains the host access described above.

`run_python_tests` uses an isolated interpreter with a controlled unittest runner that inserts the candidate project directory into its import path. `path` and optional `workdir` are relative to the task workspace. For snapshots, use `{"path":"source/tests","workdir":"source"}` or `{"path":"source"}`. When the requested directory contains `tests/`, discovery starts there, including projects whose tests directory is not a Python package. Without explicit `workdir`, a `tests` directory uses its parent; other paths use themselves. Results include `discovered_tests`, `no_tests`, and `passed`. Discovering zero tests exits with code 2 and reports `passed: false`. Import failures remain real test failures. Internal count metadata is bounded and excluded from artifacts; missing metadata never produces `passed: true`.

No live web or model service is simulated. Offline tests stub transport boundaries only; they do not establish production connectivity or credential validity.
