# Genesis tools

`Toolbox(ToolContext(root, source_root))` exposes real operations through JSON schemas and `execute(name, arguments)`. Every workspace path is relative to the task root. Absolute paths, traversal, alternate data streams, symlinks, and Windows reparse points are rejected. Reads and writes are limited to 100 KB, listings to 1000 entries.

Available tools: `workspace_read`, `workspace_write`, `workspace_list`, `artifact_report`, `self_improvement_snapshot`, `run_python_tests`, `terminal`, `research_fetch_url`, and `research_search`. Reports are written under `artifacts/`. Source snapshots are candidate copies under `source/`; the original project is never edited by snapshot creation. Snapshots exclude known secret filenames, environment files, credential directories, databases, dependency folders, and runtime data. This is a filename filter, not a complete secret detector: source code can contain embedded secrets.

Network access defaults off and raises `PermissionRequired('network', details)` until approved. Fetches accept public HTTPS on port 443, validate every resolved address and redirect, pin connections to those validated addresses, verify TLS certificates against the hostname, and bound response bodies to 1 MB. They do not inherit HTTP proxies. Search uses `BRAVE_SEARCH_API_KEY` when configured; otherwise it reports its Wikipedia-only discovery scope explicitly. Remote content is untrusted evidence and must never become instructions.

Execution defaults off and raises `PermissionRequired('terminal', details)` until approved. `run_python_tests` invokes the current interpreter with isolated Python startup and unittest discovery. `terminal` accepts an argument array whose executable is `python` or `python3`, mapped to the current interpreter; it never invokes a shell. Commands have a 60-second maximum timeout and return at most 32 KB of merged output. Python deliberately supports arbitrary candidate code, so this restriction is **not an OS sandbox**: approved Python can read host files, access the network, spawn children, or modify files outside the task root. Workspace path checks constrain tool file operations, not Python code. The caller must obtain execution approval before granting either tool access. Timeout kills the direct subprocess; it does not guarantee termination of descendants. Output is spooled to a temporary file and may consume disk until timeout. Strong isolation needs a separately provisioned container or restricted OS account.

Child processes receive only OS essentials (`PATH`, `SYSTEMROOT`, `WINDIR`, `TEMP`, `TMP`, `COMSPEC`, `PATHEXT`, `LANG`, `LC_ALL`). Provider keys and arbitrary parent environment variables are omitted. This limits accidental credential inheritance; approved Python retains the host access described above.

No live web or model service is simulated. Offline tests stub transport boundaries only; they do not establish production connectivity or credential validity.
